## Problem
Users encounter various obstacles during task execution that impede progress and lead to suboptimal solutions.

## Solution
Common implementation pitfalls identified during task execution include:
- Making assumptions about requirements instead of verifying
- Being unsure which files to modify
- Not understanding how existing code works
- Having vague implementation plans with "probably" or "maybe" elements
- Being unable to explain exact steps that will be taken
- Delivering partial work or simplified versions when full implementation was requested
- Changing scope without explicit user approval
- Making unauthorized simplifications
- Stopping before task completion
- Compromising on stated requirements
- Giving up when encountering blockers instead of consulting specialists or exploring alternatives

## What To Do Instead
- Achieve 100% certainty about user requirements before starting
- Explore the codebase thoroughly to understand existing patterns and architecture
- Create a crystal clear, step-by-step work plan
- Resolve all ambiguity by asking questions or investigating
- Consult specialists (Oracle for conventional problems, Artistry for non-conventional) when encountering blockers
- Explore alternative approaches when facing obstacles
- Deliver the full implementation exactly as requested, not demos or simplified versions
- Never change scope without explicit user approval
- Never make unauthorized simplifications
- Never stop before all TODOs are completed and verified
- Never delete or skip failing tests - fix the code instead

## Prevention
- Recognize signs of unpreparedness: making assumptions, uncertainty about files, lack of understanding of existing code, vague plans
- Implement mandatory certainty protocol before any implementation
- Use exploration agents to gather context before planning
- Schedule regular check-ins with specialists for complex tasks
- Execute manual QA as the final verification step
- Follow zero-tolerance policies for scope reduction, mockup work, partial completion, assumed shortcuts, premature stopping, and test deletion
